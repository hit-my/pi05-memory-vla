## 3. 这个模型在做什么

模型每 20 帧（0.67 秒）被调用一次，输入三张图、右臂状态、任务指令和上一次自己写的"记忆"，输出接下来 20 帧的右臂动作和一段新的记忆。记忆是固定三行文字：

```
Action:blue bowl: left -> picked | orange bowl: still
Subgoal:done 3
Task:Incomplete
```

- **Action 行**：两只碗各一句，说它在当前这一步里怎么动过。
- **Subgoal 行**：给 6 条子目标清单"打勾"。第一轮写出完整清单，之后只写 `none`（没变化）或 `done k`（第 k 条完成）。
- **Task 行**：全部完成后写 `Complete`，部署程序据此停止。

**为什么这个任务需要记忆**：两只碗一模一样，交换完成后的画面和开始时几乎相同，单看当前图像无法知道做到第几步了。

## 4. 我替你定的 5 个约定（请确认）

| # | 约定 | 具体内容 | 为什么这样定 | 改动代价 |
|---|---|---|---|---|
| 1 | **只控制右臂** | 状态 8 维 = 右臂 6 个关节角 + 右夹爪 + 右夹爪（重复一次凑够 8 维）；动作 7 维 = 右臂 6 个关节目标 + 右夹爪目标，都是绝对值（弧度）。左臂部署时保持启动时的姿态不动 | 50 条示范里左臂的 7 个数从头到尾没变过；这样现有训练代码（写死 8 维状态、7 维动作）一行都不用改 | 要双臂 14 维，需要改训练代码里约 15 处写死的维度（清单见第 9 节），并重新生成数据 |
| 2 | **三张输入图** | ① 俯视相机裁剪后画上轨迹；② 右腕相机；③ 俯视相机裁剪后的干净图。左腕相机不用 | 模型只有三个图像位，仿真里也是"轨迹图 + 腕部 + 干净主视角" | 想加左腕图要改模型结构 |
| 3 | **相机裁剪框** | 俯视 640×480 → 取 x 210–530、y 140–460 的 320×320 方块 → 缩到 256（追踪用）→ 224（模型用）。右腕 → 取中间 480×480 → 256 → 224 | 三个盘子只占俯视画面的一小块，不裁的话碗在 224 的图里只有十几个像素 | **相机位置或桌面布局变了，裁剪框必须跟着改并重新生成数据** |
| 4 | **物体命名** | 开始时在右盘的碗叫 `blue bowl`（轨迹画蓝色），在左盘的叫 `orange bowl`（橙色）。"左右"指裁剪后俯视图里的左右 | 50 条示范全部是先动右边那只，已逐条核对 | 如果真机上想允许先动左边的碗，需要补这类示范 |
| 5 | **6 条子目标** | 1 抓起右碗 → 2 放到空盘 → 3 抓起左碗 → 4 放到右盘 → 5 抓起空盘上的碗 → 6 放到左盘。边界由右夹爪开合自动切出：夹爪合上后 8 帧算"抓起"完成，张开后 5 帧算"放下"完成 | 50 条示范的右夹爪全部是整齐的"合-开"×3，不需要人工标 | 换任务要改 `real_spec.py` 和 `real_extract.py` 的切分规则 |

另外两点和仿真不同，需要你知道：

- **Action 行里的方向词是图像方向**：`left`/`right` 是俯视图里的左右，`forward`/`backward` 是俯视图里的上/下。数据里没有末端位姿，所以用碗在图像里的位移来判断，没有 `up`/`down`。
- **`Task:Complete` 出现得比仿真早**：第 6 条完成（最后一次松开夹爪后 5 帧）就标 `Complete`，此时机械臂还没收回。部署程序收到 `Complete` 后会把当前这 20 步动作执行完再停。如果希望机械臂完全收回再停，可以让它多执行一两轮，或者你在停止后自己发回零位指令。

## 5. 数据是怎么标出来的

全自动，没有人工标注。流程是 `real_robot/` 里的 5 步：

1. **取状态、动作，切子目标**（`real_extract.py`）：从右夹爪读数（约 0.94 是张开，0.01 是闭合，以 0.3 为界）找出 6 次开合。
2. **跟踪两只碗**（`real_track.py` + `real_tracker.py`）：第一帧用 SAM3 文字检测（提示词 `beige bowl`）找到两只碗，之后逐帧跟踪，全程只用当前帧和过去的帧。
3. **画轨迹图、写逐帧标注**（`real_build.py`）：每一帧生成三张 224 的图和一条标注（上一轮记忆、这一轮应该写出的记忆、未来 20 步动作）。
4. **划分和配置**（`real_assemble.py`）：最后 5 条示范（45–49）做验证，其余 45 条训练；归一化统计只用训练部分。
5. **检查**（`real_check.py`）：用训练代码自己的数据加载器把全部数据读一遍。

**数据规模**：50 条示范，16203 帧（训练 14638，验证 1565），30 帧/秒，每条约 11 秒。

**追踪是这份数据最难的地方**，请务必看一下 `preview/` 里的视频。两只碗长得一样，被夹爪或机械臂挡住后，原版 SAM3 会跟丢或者认成另一只（最初 50 条里有 17 条因此出错）。现在的追踪器加了三条规则：

| 规则 | 处理的情况 | 50 条里触发次数 |
|---|---|---|
| 重合时丢弃 | 两条轨迹落在同一只碗上：丢掉最近刚跟丢过的那条 | 26 |
| 排除法重新认领 | 一只碗跟丢 5 帧以上：重新检测，画面里"不是另一只的那只碗"就是它 | 17 |
| 合并时拆分 | 一只碗放到另一只旁边，掩码把两只都盖住：重新检测，回到和自己上一帧重叠最大的那只 | 3 |

**质检结果**：按"结束时蓝碗应在橙碗的初始位置、橙碗应在蓝碗的初始位置"逐条核对，50 条全部通过（`real_qa.py`）。两只碗的可见比例平均是 99% 和 90%；橙碗被搬运和放下后的一段时间确实被机械臂挡住，那段时间轨迹图上没有它的点，Action 行写 `occluded`，这是真实情况而不是错误。

## 6. 怎么训练

**准备环境**（仓库 README 的"需要自己准备的东西"一节有完整清单）：OpenPI 环境、`pi05_base` 权重、PaliGemma 分词器。只做训练不需要 SAM3 和渲染器，因为图已经出好了。

**步骤**：

```bash
# 1. 下载并解开数据
huggingface-cli download HITzyx/yx_bowls_memory --repo-type dataset --local-dir yx_bowls_memory
cd yx_bowls_memory/trainer_dataset && bash unpack.sh && cd -
D=$PWD/yx_bowls_memory/trainer_dataset

# 2. 按你的机器重新生成配置（卡数、batch、步数、四个模型路径）
python real_robot/real_assemble.py --out $D --contract-in $D/contract_C_real.json --contract-out $D/contract_C_real.json \
  --steps 20000 --interval 5000 --devices 4 --per-device-batch 32 \
  --openpi-root <openpi 目录> --base-checkpoint <pi05_base/params> --tokenizer <paligemma_tokenizer.model> --python <训练用的 python>
#    然后把配置里的 dataset.latents_dir 确认为 $D/latents/C（脚本会自动写成这个）

# 3. 检查（几分钟，CPU 即可）。看到 CHECK_OK 再训练
python real_robot/real_check.py $D $D/contract_C_real.json code_causal_v3

# 4. 训练。四个 PI05_* 必须和第 2 步的参数一致
cd code_causal_v3
CUDA_VISIBLE_DEVICES=0,1,2,3 PI05_DEVICES=4 PI05_PER_DEVICE_BATCH=32 PI05_TOTAL_UPDATES=20000 PI05_CHECKPOINT_INTERVAL=5000 \
XLA_PYTHON_CLIENT_PREALLOCATE=true XLA_PYTHON_CLIENT_MEM_FRACTION=0.30 PYTHONDONTWRITEBYTECODE=1 \
python -u train.py --contract $D/contract_C_real.json --dataset $D --output <输出目录> --no-wandb
```

**需要知道的几件事**：

- **从 `pi05_base` 开始训，不要从仿真的 checkpoint 接着训**。仿真模型的动作是末端位姿增量，真机是关节角绝对值，含义完全不同。
- **步数是我估的，没有依据**。20000 步、每 5000 步存一次只是一个起点：这份数据只有 1.5 万帧，batch 128 时一轮（epoch）约 114 步，20000 步约 175 轮。建议先看 5000 步的 checkpoint 在回放自检里的表现再决定。
- **资源**：4 张卡、每卡 batch 32 时每卡约占 34–38 GB 显存。卡数和每卡 batch 可以调小（我用 2 张卡、每卡 8 试跑过），至少要 2 张卡，因为存盘后的验证并行用 2 张。
- **每个 checkpoint 约 35 GB**（含优化器状态）。只做推理的话 `train_state/` 目录可以不拷。
- **存盘后会自动做验证**，期间不走步。这份数据的验证集只有 1565 帧，应该比仿真快得多，但我没有测过完整验证要多久。
- **训练期间不要改 `code_causal_v3/` 里的文件**，否则存盘时校验失败，这次存盘作废。
- **看什么指标**：`<输出目录>/training.jsonl` 每步一行。`flow7` 是动作误差，`text_ce` 是记忆文字误差。验证结果在 `validation/` 下。

## 7. 怎么部署

部署程序是 `real_robot/real_deploy.py`，它启动两个子进程（追踪器、策略服务）并自己负责画轨迹图。三部分可以用不同的 Python 环境。

**每一帧**：取俯视和右腕图像 → 裁剪 → 追踪两只碗 → 画轨迹图。
**每 20 帧**：把三张图、右臂状态、指令、上一轮记忆发给策略服务 → 得到 20 步右臂动作和新记忆 → 逐步执行。

**你需要写的只有一个类**：

```python
class Dobot:
    def observe(self):
        # top / right_wrist: uint8 [480,640,3] RGB；state: 14 个数，顺序同数据集
        return {"top": ..., "right_wrist": ..., "state": ...}
    def act(self, action14):
        # 14 个数：左臂 6 关节 + 左夹爪 + 右臂 6 关节 + 右夹爪，都是绝对目标
        ...
```

```bash
python real_robot/real_deploy.py --code code_causal_v3 --robot my_robot:Dobot --checkpoint <CKPT> --hz 30
```

**上真机之前，请按顺序做两个离线自检**（都不需要机器人）：

```bash
# 自检 1：部署的图像链路和训练数据是否一致。期望输出 "differing ... 0 of N"
python real_robot/real_deploy.py --code code_causal_v3 --replay <yx_bowls 目录> --episode 36 --compare $D

# 自检 2：模型在验证集示范（45–49）上写出的记忆对不对、动作误差多大
python real_robot/real_deploy.py --code code_causal_v3 --replay <yx_bowls 目录> --episode 47 --checkpoint <CKPT>
```

自检 2 里，训练好的模型应该在夹爪每次开合后不久写出 `done 1` … `done 6`，最后写 `Task:Complete`。如果记忆是乱码或者一直是 `none`，先不要上真机。

**部署时最可能出问题的三个地方**：

1. **实时性（我没有在你的硬件上测过）**。训练数据是 30 帧/秒，轨迹图画的是最近 21 帧。追踪这边，SAM3 之前在独占的云显卡上测得约 55 毫秒/帧/每个物体，两只碗就是约 0.1 秒一帧；策略服务每次调用在我们共用的显卡上约 1.6 秒。两者都达不到 30 帧/秒实时。这个任务是准静态的，建议的做法是：机器人执行完 20 步后**原地等待**下一次推理结果，而不是边动边推理；追踪按"每执行一步机器人动作处理一帧"来走，保持和训练时一样的步调。如果这样太慢，备选方案是把数据降到 10 帧/秒重新生成并重训。
2. **第一帧检测不到两只碗**。追踪器会直接报错退出（`bowl detection failed`）。开始时请保证两只碗都在画面内，且夹爪没有把碗挡掉大半。
3. **相机或桌面和采集时不一致**。裁剪框是按采集时的画面定的（三个盘子在裁剪后的图里大致位于中间偏左）。部署前先把一帧实时画面按 `real_spec.crop_resize` 裁出来，和 `preview/` 里的视频对比一下。

**安全相关**：模型输出的是关节角绝对目标，没有任何限幅或碰撞检查，`real_deploy.py` 里也没有加。请在你的 `act()` 里加上关节限位、单步最大变化量限制和急停。记忆格式错误不会让程序停下来（会沿用上一次的记忆继续），所以也不要把"程序还在跑"当成"状态正常"。

## 10. 仿真那边的现状（供参考）

同一套方法在 RoboMemArena 仿真上训到 2 万步，26 个任务的成功率是 39.6%（榜单最低 57.7%）。目前最主要的失败方式是：**抓空了，但记忆仍然写"已抓到"并打勾，之后不会补救**。真机上很可能遇到同样的问题，因为这份数据里也没有"抓空"的示范。如果真机上看到抓空后机械臂空着手继续走流程，这是已知问题，不是你部署错了。
